# `/api/me` — рабочая область текущего пользователя

В адресной строке UI та же идея: экраны рабочей области живут под `/me/*` (дашборд, персонал, график, договоры, организация). `/admin/*` остаётся только для администрирования системы (пользователи, справочники, аудит, генерация сменщиков). Старые `/admin/...` и `/user/...` для рабочей области редиректят на `/me/...`.

`/api/me/*` возвращает данные и операции, разрешённые вошедшему пользователю. Идентификатор, роли и организационная зона берутся из сессии. Префикс не даёт доступа ко всем данным системы.

Роль ограничивает действие. Зона (своя запись, база менеджера, подчинённые координатора, вся компания для администратора) ограничивает строки. Оба фильтра применяются в сервисе.

## Канонические маршруты

| Метод | Путь | Кто что видит |
|---|---|---|
| GET | `/api/me/personnel` | Администратор — все сотрудники. Менеджер — своя база. Координатор — прямые подчинённые. Остальным 403. |
| GET | `/api/me/contracts` | Администратор — все договоры. Менеджер — договоры своей базы. Остальные — пустой список. Архивные скрыты, пока нет `includeArchived=true`. |
| GET, PUT, DELETE | `/api/me/work-schedule` | Свой график доступен всем. Чужой график читают и меняют администратор (все) и менеджер/координатор (своя зона). Сотрудник чужой график не читает и не пишет. |
| GET | `/api/me/dashboard`, `/api/me/overview` | Те же сводки, что раньше отдавались руководителям. Сотруднику 403. |
| * | `/api/me/radar-cards`, `/api/me/ifo` | Не-администратор видит только свои записи. |
| * | `/api/me/credentials`, `/api/me/notifications` | Только собственные записи. Идентификатор из токена. |

## Совместимость

Старые пути продолжают работать и отдают заголовок `Deprecation: true`, кроме случаев, где старый путь намеренно строже.

| Устаревший путь | Преемник | Отличие |
|---|---|---|
| `/api/admin/work-schedule` (чтение/запись дней и интервалов) | `/api/me/work-schedule` | По-прежнему только администратор. Компания целиком. Заголовок Deprecation только на этих операциях. |
| `/api/team/work-schedule` | `/api/me/work-schedule` | По-прежнему только менеджер и координатор. Сотрудник получает 403, а в `/api/me` видит себя. |
| `/api/admin/work-schedule/shift-partners/generate`, `templates`, `periods` | — | Не устарели. Канонические админ-операции без аналога в `/api/me`. |
| `/api/admin/dashboard` | `/api/me/dashboard` | Тот же обработчик. |
| `/api/admin/overview` | `/api/me/overview` | Тот же обработчик. |
| `/api/radar-cards`, `/api/admin/radar-cards` | `/api/me/radar-cards` | Тот же обработчик. |
| `/api/ifo` | `/api/me/ifo` | Тот же обработчик. |
| `/api/org/employees` | `/api/me/personnel` | Список тот же. Изменение карточки остаётся на `/api/org/employees/:id`. |
| `/api/org/bases/:id/contracts` | `/api/me/contracts` | Старый путь проверяет доступ к конкретной базе. Новый собирает договоры зоны. |

## Отдельные маршруты, которые не схлопываются

Их нельзя заменить одним `/api/me` без смены смысла операции.

| Путь | Почему отдельно |
|---|---|
| `/api/admin/users` | Создание, блокировка, сброс пароля и удаление учётных записей. Это администрирование, не просмотр зоны. |
| `/api/admin/credentials` | Каталог удостоверений команды: очистка и пометка на удаление. `/api/me/credentials` меняет только дату выдачи своей записи. |
| `/api/admin/catalog`, `/api/admin/positions`, `/api/admin/org` | Изменение справочников. |
| `/api/admin/audit-log`, `/api/admin/messages` | Журнал всей системы и рассылка. |
| `/api/admin/work-schedule/shift-partners/generate`, `templates`, `periods` | Генерация смен и шаблоны на любых сотрудников. На `/api/me/work-schedule` этих операций нет: запись там ограничена зоной. |
| `/api/auth` | Вход до появления рабочей области. |
